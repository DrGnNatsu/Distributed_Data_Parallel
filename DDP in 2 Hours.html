1 · The mental model
20 min

Before touching code, get the concept precise: DDP is one process per model replica, replicas start identical, and the only thing keeping them identical is a gradient all-reduce after every backward pass — not a parameter server, not a shared model in memory.

2 · Why it's fast, from the source
15 min

The original engineering paper explains the three optimizations that make all-reduce cheap enough to hide behind compute. Fifteen minutes here saves hours of cargo-culting flags later.

3 · Build it — single-GPU simulation
45 min

You don't have a second GPU, so you'll launch two processes that both target your one GPU, coordinated over the gloo backend (CPU-side collectives), with the model and batches themselves still on cuda:0. This is the standard way to learn the DDP API without hardware — the training-loop code is identical to the real multi-GPU version.

The notebook is built for exactly this: 1 GPU, 8GB VRAM, world_size=2, gloo backend, a small CNN. Run it top to bottom in this stage.
